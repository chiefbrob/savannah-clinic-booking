Clinic booking API

Five doctors, recurring working hours, 30-minute slots. A patient sees what is genuinely free, books one, can cancel with a reason, or move it — and two patients can never hold the same slot, even if they tap at the same instant.

Why it cannot double-book

Validation produces good error messages, but it is not what protects the slot. The guarantee is a partial unique index in PostgreSQL: 

CREATE UNIQUE INDEX ix_appointments_no_double_booking
    ON appointments (doctor_id, starts_at)
    WHERE status = 'booked';

Two concurrent inserts for the same slot cannot both commit. Cancelling flips status, which drops the row out of the index and frees the slot in the same statement. The test suite fires ten simultaneous bookings at one slot and asserts exactly one 201 and nine 409s.

Status codes

201Booked
400Outside hours, misaligned, past, too soon
404Unknown doctor / patient / appointment
409Slot taken, already cancelled
422Malformed body (e.g. no timezone on a datetime)

Errors always come back as {"error":{"code","message","details"}}.

What the service does

POST /appointments validates the slot against the doctor's working hours, the 30-minute grid, and a one-hour lead time, then lets the database settle any race. GET /doctors/{id}/availability derives slots from the weekly schedule minus active bookings — nothing is materialised, so a change of hours needs no backfill. PATCH …/cancel records a reason and frees the slot. PATCH …/reschedule is a single update inside one transaction, so the patient never holds both slots or neither.

Times are returned in UTC; working hours are interpreted in Africa/Nairobi.
